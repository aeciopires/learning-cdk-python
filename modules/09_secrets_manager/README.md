# Module 09 - Secrets Manager (an auto-generated secret)

## Overview

AWS Secrets Manager stores credentials (passwords, API keys, tokens) so
your application code never has to hardcode them. This module creates one
secret with a **password Secrets Manager generates itself at deploy time**
- the CDK code and the CloudFormation template it produces never contain
the actual secret value.

## What you will learn

- **`generate_secret_string=secretsmanager.SecretStringGenerator(...)`** -
  the pattern to copy any time a module needs a password, API key, or
  token: ask Secrets Manager to generate it, never type a real-looking
  value into source code. `secret_string_template` supplies the fixed part
  of the JSON value (here, `{"username": "app_user"}`) and
  `generate_string_key` names the field Secrets Manager fills in with the
  random value (here, `"password"`).
- **Why this matters beyond style.** A hardcoded secret in source code ends
  up in git history forever, even if you change it later - generating it at
  deploy time means there is nothing sensitive to leak from the repository
  itself.
- **`removal_policy=RemovalPolicy.DESTROY`** - and why, on real AWS, this
  does not skip Secrets Manager's own recovery window. See
  [Notes and cautions](#notes-and-cautions).

## Tests

See [`../../docs/TESTING.md`](../../docs/TESTING.md) for how these work if
you haven't read it yet.

This module's tests
([`../../tests/unit/test_09_secrets_manager.py`](../../tests/unit/test_09_secrets_manager.py))
check that: exactly one secret is created, its `GenerateSecretString`
property has the expected shape (a `password` key, 32 characters, no
punctuation) and, just as importantly, the template contains no
`SecretString` property at all (this module's whole point - the actual
value is never written into the code or the template, only generated by
Secrets Manager at deploy time), the secret's name follows this
repository's naming convention, and every mandatory tag (see
[`../../REQUIREMENTS.md`](../../REQUIREMENTS.md) section 7) is present. No
Docker, floci, or AWS credentials needed:

```bash

uv run pytest tests/unit/test_09_secrets_manager.py -v
```

## Deploy with floci (local, free)

```bash
# From the repository root - see ../../REQUIREMENTS.md for eval $(floci env)
eval $(floci env)
uv run cdk bootstrap   # once per floci instance - safe to re-run; see REQUIREMENTS.md section 5.7
uv run cdk synth SecretsManagerStack
uv run cdk diff SecretsManagerStack   # what deploy would change - creates nothing (REQUIREMENTS.md section 5.11)
uv run cdk deploy SecretsManagerStack --require-approval never --method=direct
```

## Deploy to real AWS (optional)

```bash
unset AWS_ENDPOINT_URL   # stop pointing the AWS CLI/SDK at floci
uv run cdk bootstrap --profile <your-aws-cli-profile>   # once per AWS account/region
uv run cdk diff SecretsManagerStack --profile <your-aws-cli-profile>   # review the changes first
uv run cdk deploy SecretsManagerStack --profile <your-aws-cli-profile>
```

## Verify

```bash
aws secretsmanager describe-secret --secret-id "learning-cdk-python-dev-secret-app-credential"
# Prints the JSON value, including the generated password - never run this
# against a secret you actually care about keeping off your terminal history:
aws secretsmanager get-secret-value --secret-id "learning-cdk-python-dev-secret-app-credential" \
  --query "SecretString" --output text
```

Or open the floci UI at `http://localhost:4566/_floci/ui` and browse the
secret visually (see [`../../REQUIREMENTS.md`](../../REQUIREMENTS.md)).

### List every resource with the AWS CLI

Every resource this stack creates, one `aws` command each, parametrized
by environment (`ENV`), region (`REGION`) and - where a command builds an
ARN - account (`ACCOUNT`): set them to match your deployment, with your
`.env` loaded (floci) or your AWS profile active (real AWS). A resource
without a name of its own is looked up through the stack by its *logical
id* (`pid <LogicalId>`), which is the same in every environment. This block
is generated from the stack's template by
[`scripts/resource_commands.py`](../../scripts/resource_commands.py) - see
[`../../REQUIREMENTS.md`, section 5.10](../../REQUIREMENTS.md#510---listing-every-resource-a-stack-created);
`make cdk-resources STACK=SecretsManagerStack` runs the same commands for you.

```bash
# Match these to your deployment: CDK_PRODUCT and CDK_ENVIRONMENT in .env, and
# the region you deployed to (floci: the one in .env).
PRODUCT=learning-cdk-python ENV=dev REGION=us-east-1
STACK=SecretsManagerStack
# Physical id of one of the stack's resources, by its logical id - the same in
# every environment. A second argument names another (e.g. nested) stack.
pid() { aws cloudformation describe-stack-resource --stack-name "${2:-$STACK}" \
  --logical-resource-id "$1" --region "$REGION" \
  --query StackResourceDetail.PhysicalResourceId --output text; }

# Every resource the stack created - type, logical id, physical id, status:
aws cloudformation describe-stack-resources --stack-name "$STACK" --region "$REGION" \
  --query "StackResources[].[ResourceType,LogicalResourceId,PhysicalResourceId,ResourceStatus]" \
  --output table

# AWS::SecretsManager::Secret (AppSecretFAB5164C)
aws secretsmanager describe-secret --secret-id "${PRODUCT}-${ENV}-secret-app-credential" --query "[Name,ARN]" --output table --region "$REGION"
```

## Notes and cautions

- **On real AWS, deleting a secret is not instant, `RemovalPolicy.DESTROY`
  or not.** Secrets Manager schedules the secret for deletion after a
  recovery window (7-30 days, 30 by default) during which it can still be
  restored - `cdk destroy` triggers this the same way the `DeleteSecret` API
  does by default. There is no `force_delete_without_recovery` property on
  the CDK `Secret` construct to skip this from CloudFormation; that flag
  only exists on the `DeleteSecret` API/CLI call itself
  (`aws secretsmanager delete-secret --force-delete-without-recovery`), run
  outside of `cdk destroy`. See
  [Delete a secret](https://docs.aws.amazon.com/secretsmanager/latest/userguide/delete-secret.html)
  in [References](#references).
- floci emulates this differently (secrets are typically removed
  immediately on `cdk destroy`, with no recovery window), which is part of
  why `cdk destroy` in the instructions above looks instantaneous locally
  but will not be on a real account.
- Secrets Manager charges a small monthly fee per secret, plus per-API-call
  charges, on real AWS - check current pricing before leaving one running
  in a real account for long.
